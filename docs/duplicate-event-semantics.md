# Byte-identical events in branch merges

Tracked by [pm-vcs-3orq](../.agents/pm/issues/pm-vcs-3orq.toon).

## Rule and behavior

A nonblank JSONL line identifies an event by its exact bytes, including surrounding
whitespace. For every line, retain the base occurrences and append
`max(left_extra, right_extra)` occurrences. Extras are counted beyond the base on
each side. This agrees with the tree merge's identical-blob shortcut and prevents
one cherry-picked event from being replayed twice when another edit forces union.

| Base occurrences | Left extras | Right extras | Previous union count | New count |
| --- | --- | --- | --- | --- |
| 0 | 1 | 1 | 2 (shortcut: 1) | 1 |
| 0 | 2 | 1 | 3 | 2 |
| 0 | 2 | 0 | 2 | 2 |
| 2 | 1 | 1 | 4 | 3 |
| 2 | 0 | 0 | 2 | 2 |

The base remains verbatim. Appended events retain timestamp ordering and timestamp
inheritance, with stable arrival order on ties. Matching occurrences come from the
left; surplus right occurrences survive. Appended blank lines carry no event.
Native history path and line-boundary checks remain in `mergePath`; rewritten
prefixes and other blobs retain ordinary content merge. Full semantics are in
[ARCHITECTURE.md](../ARCHITECTURE.md#6-diff-and-merge).

## Regression evidence

`test/duplicate-events.test.ts` exercises 100 deterministic generated histories:
identical blobs, direct log union, an independent file edit, and a distinct appended
event that forces union. The independent file edit leaves the entire log identical;
removing the distinct event leaves the same shared log as the shortcut. Arbitrary
per-side multiplicities satisfy an independent base-plus-maximum count oracle,
including repeated base lines. Another 200 generated interleavings in
`test/review-findings.test.ts` check base prefix, multiplicity, timestamp ordering
and determinism. Separate cases preserve whitespace-distinct events, non-JSON
entries, timestamp inheritance and genuine repeated appends on one side.

Repository integration cases cherry-pick one event onto two branches or merge the
same event commit into both, then merge branch-specific events. Both keep the
shared event once. A disposable tracker writes actual PM events; all three input
hash chains verify, the real `pm merge driver history` output verifies, and its
event payloads agree with the VCS union. Comparison excludes before/after/record
hashes and reanchor evidence regenerated by the PM driver. VCS union itself does
not reanchor hash chains; PM reconciliation remains a separate operation.

Focused command:

```sh
node --test test/duplicate-events.test.ts test/records.test.ts test/review-findings.test.ts
```

Retain the new tests, documentation and exact-byte line handling. In
`mergeAppendOnlyLog`, remove the `ourAppends` / `overlap` / `theirSurplus` block and
replace the sorting input `[...ourAppends, ...theirSurplus]` with
`[...appended(ours), ...appended(theirs)]`. No whole-file replacement is involved.

```sh
node --test test/duplicate-events.test.ts
```

This exits 1: four of five tests fail (generated invariance, repeated multiplicity,
cherry-pick, PM driver agreement). The double-merge ancestry control passes because
its shared event is already in the merge base. Restoring overlap consumption
returns the focused suite to 45 passing tests, zero skipped.
