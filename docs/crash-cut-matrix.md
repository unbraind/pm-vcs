# Complete native crash-cut matrix

The lifecycle matrix builds reusable SDK/native preparation checkpoints. Each
retired-instance copy asserts that every pending plan names a missing root inside
its own disposable fixture, then republishes the identical journal bytes through
the engine to establish native publication identities. It cannot copy live
deletion authority. The interrupted-unpack checkpoint precedes interruption;
each cut performs its own real preparatory unpack SIGKILL and checks all three
physical copies before testing publication recovery.

One persistent owner per available CPU isolates engine globals, fixtures and
temporary namespaces. Each publication runs in a fresh child receiving a real
SIGKILL. Owners execute independent cuts concurrently.

When available, Bun prepares one minified Node-targeted publication entry point,
with function names preserved, and JavaScript preloads for the entire scenario.
Fatal children load prepared JavaScript instead of parsing TypeScript again. CI installs its
pinned Bun before both gates.
Without Bun the source entry point remains available. A successful probe warms
Node's compilation cache. Before scheduling cuts, the
harness compares the prepared entry point's complete syscall trace against the
source entry point's trace. The reference probe rebuilds the original fixture
from the SDK on the ordinary gate filesystem, bypassing every checkpoint. Its
complete trace must also equal the memory-backed owner trace, so changing the
temporary storage backend cannot silently remove a native boundary. Every isolated owner must pass that complete probe
before receiving cuts. Every fatal child reports its actual syscall prefix;
the owner compares that complete prefix with the recorded sequence. Recovery,
retained-data, journal, idempotency, receipt-count and descriptor assertions run
for every cut.

The purge owners also perform recovery independently, retaining the original
receipt, purge and idempotency assertions. Their original fixture source trace
must match the owners' trace before any cuts run.

The purge, proof/denial and logical scan matrices also cache completed SDK/control
initialization. They still generate and stage every original per-cut payload,
including the same seeded random sequence. The proof/denial and logical scan
fatal children use a bounded asynchronous
pool; their preparation and verification stay in the covered parent.
Synchronous preparation/recovery turns select one cut's private temporary
namespace and restore the inherited environment before awaiting a child. The
prepared probe must match the original source sequence before any cuts run.

The enumeration guard requires exactly the ordinals 1 through the recorded
boundary count, both before scheduling and after successful assertions. Each
scenario also removes the first actual recorded ordinal and requires that same
guard to reject the shortened list. The small standalone guard regression covers
the same omission independently of the expensive matrix.

Each cut has a private temporary namespace. Its owner removes fixtures and all
external namespace ledgers in `finally`, including after a fatal publication
child. Owners exit normally so V8 coverage is flushed before the parent removes
their containing namespace.
Other test entry points own a temporary scope with exit cleanup. Ordinary
workers inherit that same scope without relocating recovery ledgers; a regression
checks native ledger and fixture cleanup after both normal exit and SIGKILL.
External namespace ledgers cannot accumulate across test files. CI also retains
its gate-wide exit trap.

Both CI and local gate runs print `df -BG /` and refuse to start below
20 GiB free. Each gate owns disk and optional memory scopes and removes only
those scopes on success or failure. When at least 2 GiB are available in the
shared-memory filesystem, the disposable SIGKILL matrix namespace and the
quality-contract audit import use it to avoid disk writeback contention;
otherwise they use runner temporary storage. The packed conflict CLI acceptance
fixtures also use this configured private scope. Native power-loss model fixtures
stay on the ordinary filesystem: inode and directory behavior can change their
recorded recovery images. All native syscalls and assertions still run.
SIGKILL preserves the kernel; independent namespace power-loss tests model lost
file data and directory barriers explicitly. No test or runtime is sampled and
no threshold or timeout is relaxed.

The npm and Bun release gates run serially. Both `npm test` and coverage use the
same file scheduler, so independent matrix pools cannot overlap. The standalone
launcher is also copied into the minimal coverage-contract project; all its
omitted-source and uncovered-branch assertions remain active. A single c8
invocation collects two
complete test phases: ordinary files run on at most four available cores, then
the native SIGKILL matrix, seeded erasure-storage suite and coverage-contract
suite run serially. The remaining lifecycle and accountability assertions run in
the ordinary phase. The seeded storage suite retains its original test order
and random sequence. Twenty separate native power-model entrypoints allow those
independent scenarios to share the ordinary worker pool. A file-enumeration guard
requires exactly the declared twenty scenarios; each scenario compares the
complete syscall trace and recovery-cut ordinals against the original recording
hooks before executing every recovery image. The callbacks and image-equivalence
rules are unchanged. Private restoring hooks avoid recording unused call stacks;
a nested fault-injection regression checks restoration of the native functions.
Matrix files use their own bounded cut pools; audit imports retain every object and
all original timeout and byte-identity checks. The harness asserts that the partition contains every test file exactly
once. Source include/exclude rules and every coverage threshold are unchanged.

Matrix diagnostics report the exact recorded/executed count, wall time and
mean milliseconds spent in fixture setup,
child startup, native work before the fatal signal, signal/reap, recovery and
verification.

Release evidence uses an exact-head disposable checkout with complete reachable
history and an independent Git object database. This isolates unrelated
unreachable objects without pruning originals or changing the physical-object
identity audit. The same unchanged audit still scans every object in the
validation checkout.

The self-host audit uses the existing disposable-tree cleanup primitive for its
own generated temporary directories. It still hashes and imports every carried
object into an independent store and never regenerates during verification.
Discarding its owned scratch creates no additional recovery journal.

The retained-buffer probe excludes duplicate child coverage bookkeeping while
keeping its original 32 MiB payload, 8 MiB retention budget and deadline. The
parent suite still requires every source file to meet the existing coverage
thresholds. The stat-cache fixture derives its observation time from the file's
actual timestamp, so delayed fixture preparation cannot invalidate its racy-file
premise.

Local measurements on the retired-instance scenario used cuts 1, 409 and 818.
Mean milliseconds per cut were:

| Phase | Original | Prepared fixture/entrypoint |
| --- | ---: | ---: |
| Fixture build/copy | 1069.90 | 14.46 |
| Child startup | 897.59 | 285.27 |
| Native work before kill | 548.96 | 497.95 |
| Kill and reap | 19.30 | 8.50 |
| Recovery | 365.38 | 300.86 |
| Verification | 0.19 | 0.59 |
| Total | 2901.31 | 1107.62 |

Fixture construction dominated the original cost; native pre-cut work dominates
the prepared version. A complete uncovered original five-scenario matrix took
7,805.19 seconds for 2,751 local cuts. The initial prepared five-scenario run took
2,821.12 seconds; subsequent ownership and admission checks are included in the
release-gate measurements. Counts are derived anew on each runtime and filesystem,
not fixed to this local corpus. The CI evidence contains 3,001 cuts.

With V8 coverage enabled, the power-model hook prototype preserved all twenty
complete traces and cut arrays: 85.15 seconds and 23.34 CPU seconds became
60.55 seconds and 17.50 CPU seconds. A complete publication-recovery scenario
preserved all 597 observed boundaries and 71 recovery images: 24.83 seconds and
11.90 CPU seconds became 15.28 seconds and 8.91 CPU seconds. These prototype
counts describe that filesystem; the live oracle compares freshly recorded
sequences rather than assuming those counts apply elsewhere.
